# Evidence: Kafka broker failover test (9 Nov 2026)

**Result:** with one of three brokers stopped, every partition kept a leader and 2 in-sync replicas, so writes stayed possible and no data was at risk. The stopped broker rejoined automatically, and Kafka moved leadership back to it within about 8 minutes.

## Setup

- Cluster: 3 Kafka 4.4.0 brokers in KRaft combined mode (`kafka-1`, `kafka-2`, `kafka-3`), started with `docker compose up -d`
- Topic: `adsb.positions`, 6 partitions, replication factor 3, `min.insync.replicas=2`, `unclean.leader.election.enable=false`
- Command used to inspect the topic each time:

```
docker exec -e KAFKA_HEAP_OPTS=-Xmx128m kafka-1 /opt/kafka/bin/kafka-topics.sh --bootstrap-server kafka-1:19092 --describe --topic adsb.positions
```

## Limits of this test

- No messages were flowing yet, so this shows that leadership and replication recovered, not that a live stream continued without loss. That test follows once the producer runs.
- All three brokers run on one laptop, as a simulation of three machines.
